# 消費統計 — Expenses_Analysis

個人消費與收入統計 PWA。離線可用，零外部依賴，資料只存在你的裝置。

## 部署

```bash
# 1. 在 GitHub 建立 repo：Expenses_Analysis
# 2. 把本資料夾全部檔案推上去
git init
git add .
git commit -m "v1"
git branch -M main
git remote add origin https://github.com/tcfmacau1/Expenses_Analysis.git
git push -u origin main
# 3. Settings → Pages → Source: main / (root)
```

上線網址：`https://tcfmacau1.github.io/Expenses_Analysis/`

手機 Safari 或 Chrome 開啟後，分享 → 加到主畫面。之後飛航模式也能用。

**必要檔案**：`index.html`、`sw.js`、`manifest.webmanifest`、`icon-192.png`、`icon-512.png`。

`index.html` 已內嵌全部程式，**單獨一個檔案就能開**（雙擊、file:// 都可以），只是沒有
PWA 的加到主畫面與離線快取。`core.js`（運算）、`app.js`（介面）、`build.py`、`test_*`
是開發用：改了 `core.js` 或 `app.js` 都要跑 `python3 build.py` 重新注入 `index.html`，
否則改動不會生效。

## 四個分頁

| 分頁 | 做什麼 |
|---|---|
| 記一筆 | **開 App 的落地頁**。支出／收入／轉帳三種，輸入金額 → 點大類 → 記錄；子類與帳戶自動預選最常用的 |
| 統計 | 消費基準與現金基準兩種結餘；還卡紀錄；信用卡未還；十大類地層剖面；與近三月同期對照；帳戶別支出 |
| 紀錄 | 當月流水，點任一筆可改行程歸屬、修改、刪除 |
| 設定 | 雙層帳戶管理、固定支出範本、行程、資料匯出入、規則說明 |

## 幾條寫死的規則

- **對照用同期天數**：本月 1 到今天，比前三個月同樣的 1 到今天。不比整月。
- **樣本不足不下結論**：可用月份少於 3 個時只顯示「累積中」，不亮紅綠燈。
- **異常提示**：某大類超出近三月同期均值 30%，且該類近三月全月均值達 2,000 MOP。
  低於這個金額的類別永久靜音，但畫面仍會列出「被靜音的超標」，不會假裝沒事。
- **旅行隔離**：行程期間內的支出自動歸入該行程，統計預設不含它們。結餘則含（那是真的花掉的錢）。
- **家庭支出的邊界**：先看有沒有別的大類能裝。買菜→日常採買，全家吃飯→餐飲。
  只有無家可歸的（學費、補習、家用現金）才進家庭支出。
- **措辭一律「已記錄」**：沒有跟帳單對帳，數字只代表你記到的。
- **信用卡雙軌**：刷卡當下記消費（那是構成），現金流出算在下個月（那是現金）。
  **找數那一筆永遠不記**——它是資金搬運，記了就雙重計算。
  應找卡數＝上個月整月的刷卡總額，是估算，不等於帳單（多數卡月中結帳）。

## 資料

只存 localStorage。清除瀏覽器資料或換手機會歸零。設定頁有「距上次匯出 N 天」計數器，
超過 30 天會轉紅。JSON 可匯出也可匯入還原，CSV 供 Excel 使用（含 BOM）。

## CSV 匯入

設定頁的「匯入 CSV（附加紀錄）」。**CSV 是附加，不是取代**——JSON 才是取代全部的還原。
選檔後會先出預覽：可匯入幾筆、重複略過幾筆、有問題幾筆（逐行列出原因），確認才寫入。

欄位規則：

- **以欄位名稱對應，順序可以亂。** 必要欄位只有三個：`日期`、`型別`、`原幣金額`。
- `型別` 要是 `支出`／`收入`／`轉帳`。
- **日期只接受** `2026-08-01`、`2026/8/1`、`2026.8.1`。`01/08/2026` 這種會被拒絕——
  日月順序有歧義，猜錯比報錯更糟。
- 金額吃得下千分位（`12,345.67`）與 `MOP` 前綴。
- **金額一律用「原幣金額 × 匯率」重算**，不採用匯出檔裡的「澳門幣金額」欄——那是顯示值。
  外幣若缺匯率，會用「澳門幣金額 ÷ 原幣金額」回推；都沒有才報錯。
- **大類認不得就報錯**，不會偷偷丟進「其他」——大類是鎖死的，中途混入新類會斷掉對照基準。
- 子類、帳戶認不得會**自動新增**並在預覽中列出（這兩者本來就可擴充）。
- `行程` 用名稱對應：對得上就沿用；對不上會新建一個行程，起訖日由該行程的資料範圍推出。
- **完全一樣的行會自動略過**（同日期、型別、金額、幣別、分類、帳戶），檔案內部重複也只留一筆。
  這讓你可以放心重複匯入同一個檔。

## 點大類看子類

統計頁的地層剖面，**每一層都可以點開**。點「餐飲」會就地展開該類的子類明細：

- 預設只列**佔比最前三項**，其餘併成一行「其餘 N 項」——超過三項就不再是一眼看懂。
- 每項顯示筆數、佔該大類的百分比、金額。同一子類的多筆會合併。
- 子類超過三個時有「展開全部」可切換。
- **佔比的分母是該大類**，不是全月總額——你要問的是「餐飲裡面誰最貴」。
- 展開狀態跟著當前的旅行檢視與同期天數走，換月份會自動收起。

## 資料模型

三種紀錄型別共用一個 `entries` 陣列：

| 型別 | 欄位 | 進統計嗎 |
|---|---|---|
| `expense` | cat / sub / pay / acct | 進支出構成 |
| `income` | cat / sub / pay / acct | 進收入 |
| `transfer` | fromPay / fromAcct / toPay / toAcct | **都不進**，只影響現金流 |

舊版（付款方式四選一）的資料開啟時會自動遷移：現金→現鈔、手機支付→MPay、
銀行轉帳→未指定帳戶，舊卡片 id 對回帳戶名稱。遷移只跑一次，schema 升到 3。

## 大類（上線後鎖死）

餐飲｜交通｜日常採買｜居住｜保險供款｜訂閱通訊｜個人健康｜娛樂社交｜家庭支出｜其他

子類可在記帳時隨時新增。大類不可增刪——中途改結構會讓前三個月的對照基準斷裂。

## 出錯時

畫面上方會出現紅色橫幅，直接寫出錯誤訊息與行號——手機沒有 devtools，所以錯誤自己現形。
把橫幅截圖下來就能定位問題。

## 外觀

配色取自多啦A夢：主藍 `#00A0E9`、白面板、頸圈紅 `#E60012`、鈴鐺黃 `#FFC800`，
圓角與膠囊按鈕。異常類別加紅框與「！」。只取配色，不含任何角色造型。

換配色只要改 `index.html` 開頭 `:root` 那一段的 CSS 變數，不必動任何邏輯。
`--s1` 到 `--s8` 是地層剖面由大到小的八階色。

## 換自己的圖示

主畫面圖示就是這兩個檔，換掉即可，**檔名與尺寸不要改**：

| 檔案 | 尺寸 | 用途 |
|---|---|---|
| `icon-192.png` | 192×192 | Android 主畫面、iOS `apple-touch-icon` |
| `icon-512.png` | 512×512 | 啟動畫面、大尺寸顯示 |

幾個會踩到的地方：

- **iOS 不支援透明背景**，透明處會變黑。一定要填滿底色。
- **iOS 不會自動裁圓角**，系統會自己套用圓角遮罩，所以圖示畫成正方形即可。
- **重要內容留在中央 80% 之內**。Android 的 maskable 模式會裁掉外圈，邊緣的東西會不見。
- **換完之後 iOS 不會自動更新**：要把主畫面上的舊圖示刪掉，重新「加到主畫面」一次。
  Android 通常重新整理後就會換，必要時也是移除再加。
- 想改開啟時的底色與狀態列顏色，改 `manifest.webmanifest` 的 `background_color`、
  `theme_color`，以及 `index.html` 裡的 `<meta name="theme-color">`（三處要一致）。
